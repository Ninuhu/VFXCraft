# VFXCraft プロジェクト仕様

版: 1.0 / 2026-11-03  
製品要件の正本。技術設計とUI配置は別文書で管理する。

## 1. 目的と基本方針

VFXCraftは2D・3Dゲームエフェクトを制作するWebブラウザ向けツール。初期開発目標を**MVP-B**と呼ぶ。プリセットまたは素材からエフェクトを作り、複数レイヤー、パーティクル、タイムライン、キーフレームで調整し、編集可能なプロジェクトとゲーム向け出力を得る。

- 初期プラットフォームはWebブラウザ。デスクトップアプリは将来対応。
- 2D・3Dを別々の編集モードとして提供する。
- UIのレイアウトとデザインはユーザーが決める。
- MVP-BではAIを必須にしない。AIなしで基本機能をすべて使える。
- CodexとGitHubを使う開発方針。リポジトリの作成・接続・公開はこの文書作成には含まない。

## 4. MVP-Bの完成条件

1. Webブラウザ上で2Dと3Dそれぞれの制作フローが最後まで通る。
2. 連続発生・Burst、複数レイヤー、全必須描画方式が使える。
3. 位置・回転・サイズ・色・透明度のキー、開始時間、再生・コマ送り・速度・ループ、両スナップが機能する。
4. 階層、基本操作、ロック、最大100操作のUndo/Redo、指定された種類のショートカットが機能する。
5. 50種類以上の内蔵プリセットが読み込み・編集可能。自作プリセットの保存・読み込み・再編集、3画像形式の素材読込ができる。
6. `.vcr`保存→閉じる→開くで編集内容と素材が復元する。ブラウザ内自動保存からも復元できる。
7. 指定条件のPNG連番・スプライトシートを出力でき、3D設定JSONも出力できる。
8. カメラ・背景・統計表示、テーマ・日英切替・設定保持・ヘルプが機能する。
9. ユーザーが設計したUI配置が製品画面へ反映されている。仮画面のまま完成扱いにしない。
10. [TEST_PLAN.md](TEST_PLAN.md)の必須確認が完了し、既知の重大な不具合がない。

対応ブラウザ、基準端末、負荷条件、目標FPS、最大粒子数、最大出力サイズなどの具体値は未決。[DECISION_LOG.md](DECISION_LOG.md)の技術判断で実装前または該当工程前に定義する。未測定の性能を保証しない。

## T04〜T10のユーザー決定（2026-11-07）

各節のQ番号はユーザー回答の識別子。既存の要件IDとMVP-Bの必須範囲は維持し、重複する従来記述は本節に従う。

### T04 素材付きプロジェクトの保存・読込

- Q01　保存対象プロジェクトに登録された全インポート画像を、使用有無にかかわらず `.vcr` に同梱する。
- Q02　T04初版のファイルを将来のVFXCraftで開いて再編集できるようにする。
- Q03　同じファイルへの上書き保存を基本とし、非対応ブラウザでは明示的にダウンロードへ切り替える。
- Q04　未保存変更がある状態で別プロジェクトを開く場合は、保存して開く・保存せずに開く・キャンセルを提示する。保存失敗、取消、破損・読込失敗では現在の文書・履歴・素材を維持する。
- Q05　保存失敗の原因を表示し、再試行と別の場所への保存を選べるようにする。編集内容と未保存状態を維持する。
- Q06　自動保存の復元候補と日時を表示し、ユーザーが対象を選ぶ。本体はT11で実装する。
- 追加Q02　ダウンロード開始時には保存済みにしない。通常保存と「保存して開く」の両方で、ユーザーが実ファイルの保存完了を確認した時点で、対象スナップショットを保存済みにする。後続編集は未保存のまま扱い、確認取消時は現状を維持する。確認後に「保存して開く」の読込へ進む。利用者による確認とアプリによる完全性検証は表示上区別する。

### T05 2Dパーティクル描画

- Q01　Continuousは時刻0から発生し、Burstとは独立した方式とする。
- Q02　寿命、発生率、初速、方向、一定加速度を設定できる。発生形状は少なくとも点・円・長方形。
- Q03　発生器ごとにワールド／ローカルのシミュレーション空間を選び、生成済み粒子の親・発生器への追従を制御する。
- Q04　ピクセル表示は2・4・8倍などの整数倍率とNearest-neighborに対応する。
- Q05　正確／軽量プレビューを切り替えられる。軽量表示は保存データと最終出力に影響させない。
- Q06　T05から同じ設定・シード・時刻での再現性を目指す。MVP-B後はランダム範囲・固定シードUIを高度な発生形状エディタより優先する。

### T06 3Dパーティクルとカメラ

- Q01　カメラへ全面的に向く方式と、Y軸を固定してカメラ方向を向く方式を選べる。
- Q02　透明粒子の深度ソートをレイヤー順より優先し、限界とトレードオフを設計資料に記録する。
- Q03　固定初期視点へのリセットとエフェクト全体表示を別操作として提供する。

### T07 マテリアル・合成・Bloom

- Q01　粒子寿命に沿う時間方向と、粒子内の位置に沿う空間方向のグラデーションに対応する。
- Q02　マテリアルごとにBloom強度を調整できる。実現可能性と性能を事前に検証する。
- Q03　ピクセル2Dではピクセル感を維持するBloomと滑らかなBloomを選択できる。
- Q04　背景色、透過チェッカー、グリッドは共通設定を基本とし、プロジェクト固有設定で上書きできる。
- Q05　透明PNGは明暗両背景で自然な発光を目指す。合成条件による差をT13で検証し、全環境での完全一致は保証しない。
- Q06　寿命・空間のそれぞれで、複数の色制御点と透明度制御点を独立して編集できる。
- Q07　基本値、寿命グラデーション、空間グラデーション、画像テクスチャのRGBと透明度をそれぞれ乗算する。
- Q08　合成方式は通常・加算・乗算。マテリアルごとに選び、初期値は通常とする。
- Q09　Bloomの強度はマテリアル別、半径としきい値はプロジェクト全体で共通とする。
- Q10　ピクセル2Dの粒子本体とBloomを別々に描画し、整数倍率で本体のドット感を維持する。
- Q11　変更した背景項目のみプロジェクトの上書きとして保存する。共通設定は利用者の設定領域に保持する。
- Q12　軽量プレビューはBloomの負荷を下げる。設定、粒子の評価結果、履歴、最終出力の品質に影響させない。

### T08 タイムラインと基本キー

- Q01　ループは終端フレームを含めない。手動シークと停止時は終端を表示できる。
- Q02　レイヤーごとに発生開始・終了時刻を設定する。終了時刻以降は新規発生を止め、生成済み粒子は寿命まで生存する。
- Q03　制作尺の短縮で範囲外になるキーは、保持・削除・取消から選ぶ。保持したキーは警告と編集手段を維持する。尺変更と削除は単一Undoで戻せる。発生終了とキー有効範囲は独立する。
- Q04　タイムラインのドラッグと正確な数値入力でキーを編集できる。
- Q05　キーとレイヤー開始位置のドラッグにフレームスナップを適用する。数値入力とプレイヘッドには強制しない。
- Q06　時間軸の水平ズーム・スクロールに対応する。
- Q07　キー一括編集とカーブエディタはMVP-B後とする。
- Q08　LinearとStepを区間ごとに選ぶ。区間の左キーが方式を持ち、3D姿勢のLinearは最短経路SLERPで補間する。
- Q09　位置・回転・スケール、発生率・寿命・初速・方向・加速度・粒子サイズ、材質色・透明度・Bloom強度、レイヤー色・透明度をキー化する。寿命と粒子の運動・サイズ設定は発生時に固定し、ローカル空間の変換と外観は現在時刻で評価する。
- Q10　同一トラックの同時刻キーは禁止し、異なるトラックでは同時刻を許可する。
- Q11　キーなしでは基本値を使う。キーがあるトラックは先頭前・末尾後で端点を保持する。論理版1〜4の互換動作はADR-011に従う。
- Q12　キー移動の衝突では上書きまたは取消を確認する。上書きは一操作とし、Undoで両方のキーを復元する。
- Q13　秒と制作フレームを表示・入力で切り替えられる。制作FPSを変更しても、キーは整数マイクロ秒で同じ時刻を保持する。
- Q14　再生速度は0.25・0.5・0.75・1・1.25・1.5・2倍。初期値は1倍。速度はプレビューの時間進行にだけ作用する。
- Q15　再生は現在位置から開始し、一時停止は時刻を維持、停止は0へ戻る。非ループでは終端で一時停止する。

### T09 レイヤー階層・編集補助

- Q01　通常のエフェクトレイヤーも子レイヤーを持てる。
- Q02　親変更時は現在のプレイヘッド時刻のワールド空間での見た目を維持する。変換を表現できない場合は理由を示して拒否する。
- Q03　子の開始時刻は親と独立し、親の開始時刻変更で移動しない。
- Q04　親の表示、色、透明度を子へ継承する。合成式は実装設計で定義する。
- Q05　親ロックは子孫のプロパティ、キー、階層、削除を保護する。選択、表示切替、ロック解除は可能とする。
- Q06　確認後に親と子孫をまとめて削除する。子を一段上に移す解除操作は別に設け、両操作とも単一Undoにする。ロックされた子孫を保護する。
- Q07　子階層、キー、発生器、マテリアル設定を独立複製する。画像バイナリは共有できる。
- Q08　位置スナップはワールド／親ローカルを切り替えられる。粒子シミュレーション空間とは独立する。
- Q09　2D・3Dそれぞれでスナップ間隔を変更でき、表示グリッドの間隔も連動する。
- Q10　再親子化は現在のプロジェクト時刻のワールドTRSを維持する。必要なローカルTRSがShear、特異行列、非有限値などで表現できない場合は変更全体を拒否する。アニメーションの他時刻の軌道は保証しない。
- Q11　現在時刻の祖先から子までRGBとAlphaを成分乗算し、表示は祖先の非表示を継承する。子自身の保存値とマテリアルは変更しない。
- Q12　親子の発生期間とキー時刻はプロジェクト基準で独立する。再親子化では開始・終了・既存キーの時刻と補間を維持する。
- Q13　ロック中の親への子追加・移動・複製を禁止する。コマンド経由でも保護し、ロックの自動解除はしない。

### T10 UI統合・ショートカット

- Q01　UI v1.0の9画像を正式な画面構成の基準とする。小規模な補完はデザインの範囲内で行い、大幅なレイアウト・画面遷移の変更は事前承認を得る。画像の表記と確定仕様が矛盾する場合は確認する。
- Q02　キー割り当てを変更・保存できる。複製はCtrl+Dとし、他の初期候補はUI要件を参照する。ブラウザ・OSとの競合、文字入力・日本語IME、キー重複を検証する。
- Q03　ホームに加え、エディタのファイルメニューまたはCtrl+Alt+Nで新規作成ダイアログを開ける。未保存変更にはT04-Q04を適用する。
- Q04　1プロジェクト1モードを維持し、2D・3D間の変換・混在の方針決定はMVP-B後とする。

#### T10追加決定（2026-11-23）

- Q05〜06 パネルのサイズ・表示・ブラウザ内配置を変更でき、利用者共通設定へ自動保存する。初期配置へ復旧できる。.vcrへ混入しない。
- Q07 空・基本粒子入り・サンプルの三方式で2D/3Dを新規作成する。
- Q08 有効な入力候補を即時プレビューし、連続操作一回を一履歴にまとめる。不正値・取消は確定しない。
- Q09 Ctrl追加解除・Shift可視範囲の複数選択。編集は最後のアクティブ一層のみで、一括編集はしない。
- Q10 2D/3Dの選択・移動・回転・尺度ギズモを既存の編集軸・位置スナップ・ロック・履歴へ接続する。
- Q11 Auto Keyは初期OFF。ONでは現在時刻の対応プロパティのキーを追加または更新し、同時刻の重複を作らない。
- Q12 寿命・空間のRGB/Alpha制御点を正式画面で独立編集する。既存の補間・検証を再利用する。
- Q13 アプリ内の破棄操作は保存・破棄・取消。ブラウザ離脱は未保存時だけ標準警告を使う。
- Q14 同時編集は一プロジェクト。読込成功時だけ文書・選択・履歴・資源を切り替える。
- Q15 後続画面の入口と基本配置を整え、未実装機能を動作可能に見せない。
- Q16 主要操作の説明をマウスとフォーカスで表示し、ショートカット変更に連動する。
- Q17 割当の変更・解除・復旧・共通保存を提供し、重複時は元割当解除の確認または取消を行う。
- Q18 プロジェクト自動保存・日時付き候補・選択復元を正式UIへ接続する。自動保存は明示保存済み状態を変更しない。
