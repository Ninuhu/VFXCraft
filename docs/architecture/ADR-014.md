# ADR-014 保存・自動保存・復元の整合性

状態: 採用。2026-11-25 / T11。要件REQ-Q10-01/06、検収AT-11/12。

## 既存方式を再利用する

ADR-004のZIPコンテナ版1・論理文書版6、厳格なパス・CRC・エントリ数・容量・画像検証を変更しない。ProjectFileFlowの保存開始時スナップショット、Blob参照保持、ファイル操作排他、保存先の成功後更新、ダウンロード後確認、検証成功後の文書置換を維持する。保存失敗・取消で以前の保存先と文書を保持する。T03の一意な履歴識別子で明示保存位置を管理し、自動保存からmarkSavedを呼ばない。

## 確定状態に基づく自動保存

AutosaveControllerは文書の確定revisionを観測する。UI再描画・再生・選択変更ではタイマーを延ばさず、確定編集後2秒で一回保存する。連続編集中はタイマーを止め、途中の仮状態を保存しない。圧縮とDB書込を同一セッション内で直列化し、成功したrevisionのみ重複抑止する。失敗後は明示再試行または次の編集を待ち、無限再試行しない。文書切替前にflushを試み、待機中の追加編集を検出して切替を中止する。自動保存失敗を通知しても、明示的に破棄を選んだ操作を恒久的に禁止しない。

Controllerはセッションの効果が所有し、アンマウントでタイマーと通知を止める。進行中のIDBトランザクションは完了またはabortまで独立して進む。プロジェクト本体・画像参照は最初のawait前に固定され、別文書の保存状態へ影響を与えない。

## 世代・複数タブ・保持方針

IndexedDB `vfxcraft-project-recovery` を版2へ非破壊更新する。旧snapshotsストアを保持し、generationsストアを追加する。候補キーはタブ起動ごとのUUIDと単調な世代番号。同じプロジェクトを別タブで編集しても別レコードへ追加する。DBのaddは既存候補を上書きせず、完成アーカイブ・名前・モード・プロジェクトID・タブID・世代・日時を一トランザクションで保存する。

端末時計は表示順だけに使い、競合の勝者を決定しない。同一日時でも各候補は独立する。利用者はタブ・世代・日時を見て復元する。共同編集・ファイルハンドル間の排他保存を提供するものではない。

ユーザーの「自動削除の新仕様を無断導入しない」という指示に従い、T10暫定の最近3プロジェクト回収を取り除く。過去候補を削除せず容量不足では新規書込を失敗として通知し、.vcrへの明示保存を促す。保持期間・世代数・利用者による整理UIの最終製品ポリシーは未確定。利点は正常世代と他タブを保護できること、欠点は長時間利用で容量・一覧件数が増えること。暗黙の削除より、上限到達を明示する方式を採用する。

## 破損・容量不足・接続

一覧ではDBの値をunknownから検証し、メタデータが不正な候補の件数を通知して隔離する。レコード自体は削除しない。ZIP・文書・画像の完全検証は候補選択時に共通readVcrへ委譲し、失敗で編集中の文書を変更しない。復元した文書は新しい履歴・未保存状態で開始する。保存先ハンドル・Undo履歴・UI操作状態は復元対象にしない。

IDBの成功はrequest成功ではなくtransaction完了で判断する。容量不足・abortで直近正常世代を残す。接続はfinallyで閉じ、versionchangeでも閉じる。blockedで拒否した後の遅延成功も即座に閉じる。ブラウザ・プロファイル・オリジンの違いや利用者のストレージ消去、ブラウザの退避・終了による喪失を防ぐ保証はしない。離脱時イベントだけに保存を依存させない。

接続開始中のPromiseは同一タブ内で共有する。React StrictModeの再マウント等で接続開始を重ねると、最初のnative要求だけがblockedを受け、後続要求がキューで待ち続ける可能性がある。blockedで一度拒否してもnative要求は取消できないため、その要求が成功/失敗するまで同じ拒否を共有する。解放後の遅延成功では接続を閉じて共有状態を解除し、次の再試行を可能にする。成功した接続を恒久的にキャッシュする方式は採らない。
