# ADR-005 編集コマンドと履歴

状態：T03で履歴部分を採用（2026-11-05）。階層操作の製品挙動はOPEN-05としてT09で扱う。

## コマンドと検証

編集は型付きコマンドで表す。コマンドから現行文書を変更せずに候補を作り、T02の検証に成功した候補だけを確定する。無効な操作は文書、履歴、保存済み位置に影響しない。レイヤー、基準パラメータ、キー、材質の素材参照、親子関係の操作を共通の経路に通す。

T03の親変更は親IDだけを書き換え、ローカル座標を保持する。子が残る親の削除は参照エラーとして拒否する。レイヤーの削除に伴いそのTrackを除去する。キーの最後の1件を削除したときはTrackも除去する。画像素材を削除すると、同じ操作で材質から当該素材への参照を解除する。Undoは削除前の素材メタデータと参照をまとめて復元する。

## 履歴と保存済み位置

- 確定した文書を不変のスナップショットとして保持する。変更のない論理データは共有し、Undo・Redoは現在位置を移動する。個別の逆操作を用意せずに、関連する変更をまとめて復元できる。
- 基準状態1件と最大100件の編集結果を保持する。101件目では先頭の状態を除去する。Undo後に有効な新規編集を確定するとRedoの分岐を破棄する。
- 状態ごとに再利用しない識別子を発行する。保存処理は開始時に確定済みスナップショットを受け取り、保存成功後にそのスナップショットで通知する。現在位置の識別子と保存位置の識別子が一致する場合に保存済みとする。同じ値に手入力で戻った編集や、履歴上限・分岐で失った状態は一致しない。通知が来た時点で別の操作に進んでいても、実際に保存した状態を記録する。
- 新規作成と別プロジェクト読込では、入力の検証成功後に履歴を初期化する。新規は未保存、正常に読み込んだ文書は保存済みとして開始する。旧セッションからの保存通知は無効。再生・プレビューカメラ・テーマの状態は編集コマンドの範囲外とする。
- 実質的な無変更は新しい状態を発行しない。Quaternionは符号が異なる同じ姿勢と、再正規化の丸め差を無変更として扱う。保存判定は履歴識別子で行う。

## 連続入力

ドラッグ・数値入力で同じ開始、更新、確定、取消APIを使う。更新は候補を検証してプレビューだけを差し替える。不正な途中値は最後の有効なプレビューを維持し、有効な更新に戻るまで確定を拒否する。確定では開始位置と比較して最大1件を記録し、取消では候補を破棄する。

1回に許可する連続編集は1件。連続編集中は単発編集とUndo・Redoを停止し、操作トークンで終了済みの入力イベントを識別する。新規作成・読込が成功した場合は連続編集も終了する。保存対象として公開する文書は確定済みの状態で、プレビューは別に取得する。

## 素材と後続タスク

履歴には素材IDとメタデータを保持し、画像本体は外部ストアが所有する。回収判断に使えるよう、現在位置、Undo・Redoで到達できる状態、プレビューで必要な素材IDの集合を返す。T04の素材ストアでは履歴が保持するIDを同じ素材本体に結び付け、保存処理自身が必要とする素材も処理の終了まで保持する。非同期保存の書き込み順序、.vcrの保存・復元、素材本体の回収はT04で扱う。親削除・再親子化・ロックと表示の継承はT09に、操作のUIへの接続は各編集タスクに引き継ぐ。

スナップショットの共有で画像本体や未変更の文書部分の複製を避けつつ、Undo・Redo時の再検証を省ける。編集時は文書全体を検証して比較するため、大規模文書や高頻度の入力では処理時間の測定が必要になる。代表的な文書で負荷を確認し、必要になった段階で差分検証を検討する。
