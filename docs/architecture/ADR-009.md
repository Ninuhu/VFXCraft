# ADR-009 3D粒子・透明ソート・カメラ

状態：T06で採用（2026-11-08）。Three.jsは既存の0.186.1を利用。追加依存なし。製品挙動はPROJECT_SPECのT06-Q01〜Q03とユーザーのT06実装指示に従う。

## 評価と保存モデル

論理スキーマ版3にparticle3dを追加する。速度は非負、方向は有限・非ゼロの3成分で保存し評価時に単位化、加速度は有限の3成分、空間はworld/local。点発生のみ。シードはuint32として保持するが、点と一定方向には乱数の消費が不要である。値の範囲を持つランダムUIと追加形状は先行実装しない。

Continuousは時刻0の粒子番号0から、Burstは時刻0に指定数を発生する。寿命区間は開始を含み終端を含めない。T05と発生番号・境界の処理を共有し、位置は一定加速度の解析解で計算する。2Dの形状・乱数処理は維持する。3Dは右手系Y上正、位置はワールド単位、速度は単位/秒、加速度は単位/秒²。方向と加速度は発生器の基底で指定する。ワールドでは発生時の親変換を使い、ローカルでは現在時刻の変換を使う。設定編集後は現在の文書から過去時刻も再評価する。

親の位置・Quaternion・非一様スケールを子から順に合成する。粒子の中心は合成した変換で求め、板の幅と高さはローカルX/Y基底を合成した長さから得る。板自体はビルボードの基底を優先するため、階層由来のせん断形状を板へそのまま適用するものではない。元の板の基準寸法は0.2ワールド単位。階層の製品編集や継承はT09に残す。

コンテナ版は1を維持する。論理版1/2は読込時に版3へ移行し、既存2D設定と素材を保持する。3D発生器の既定は速度0、方向[0,1,0]、加速度[0,0,0]、ローカル、シード1、点、全面ビルボード。旧版に運動を規定する保存値がないため、既存の寿命と発生設定を保持して静止を補う。未知版は拒否する。T04の固定検体は変更せず、T05版2の互換性検体を追加する。

## ビルボードと透明描画

全面追従はカメラのワールド右・上基底を使うスクリーン平行の板。Y固定はワールドYを上方向にし、カメラ位置と粒子中心の水平差から右方向を得る。水平差が退化する真上・真下ではカメラ右方向の水平射影、さらに退化した場合はX正方向を使う。一意な水平方向が存在しない極ではこの規則で有限性を維持する。

全レイヤーの粒子を集め、視線方向の距離で遠方から近方へ安定ソートする。同じ深度はレイヤーUUIDと粒子番号のキーで決める。レイヤー順を優先しない。Y固定も含め、板の中心深度で近似するため、交差する大きな板や循環した遮蔽を厳密に解くことは保証しない。微小な深度差は量子化せずそのまま比較する。

ソート後の六頂点とRGBAを一つの動的BufferGeometryに詰め、単一Mesh・基本アルファ合成・depthWrite=falseで描く。標準のオブジェクト単位ソートへ粒子順序を委ねない。CPU配列とGPUバッファは最大同時数に合わせて再利用し、増設時と破棄時に解放する。頂点は有限かつFloat32の安全範囲内か確認する。高度な色合成、テクスチャを含む材質別の描画、加算とBloomはT07で扱う。T07で材質を分ける際も全体順序を保つバッチ分割が必要になる。

## カメラと入力

カメラ状態は文書・履歴から独立する。左ドラッグOrbit、右またはShiftドラッグPan、ホイールZoom。入力購読は解除可能にし、極を避ける角度・距離・注視点の防御上限を設ける。異常値は適用前に拒否する。単位mへの換算は確定していないため、検証UIではワールド単位を使う。

固定リセットは位置[4,3,6]と注視点原点へ戻す。全体表示は現在のプレイヘッドで生存する粒子と板の幅・高さを含むBoundsを使い、水平・垂直の狭い半画角に包含球を収める。現在の視点方向は保持する。空のエフェクトではカメラを変更せず説明を表示し、非有限値や表示範囲外のBoundsも変更前に拒否する。全時間の軌跡を走査する操作は追加しない。

## 履歴・UI・資源

発生器更新とレイヤー更新はT03のコマンド経路を使う。数値入力は開始〜確定を1操作にまとめ、取消や無効値では確定文書を維持する。保存はT04のスナップショットと読込検証を利用する。開発用UIは /?particles3d-review。GPU、イベント、ResizeObserverとrequestAnimationFrameはマウント所有者が破棄する。

UI v1.0の9画像は作業ツリーから欠落しているが、コミットbd4d75eとプロジェクト内のt04-preflightバックアップに存在し、Git blobの一致を確認した。外部コピーや復元は行わず、既存の正式採用状態を維持する。T10での製品UI統合前にユーザーが復元元・登録先を確認する。

## 検証と性能の限界

単体テストで発生・運動、親変換、空間、ビルボードと極、全体深度順、頂点、不正入力、カメラ、履歴と旧版保存を検証する。Chrome/Edgeでは実画素の赤青重なりをカメラ反転前後で比較する。

評価、深度計算とソート、頂点構築、renderer.renderのCPU時間を別々に記録する。最後の区間はバッファ転送指示と描画投入を含み、GPU実行時間そのものではない。CPUバッファ容量とThree.jsの資源カウンターでメモリ傾向を確認する。GPU時間とブラウザ全体のヒープ使用量は未測定。性能目標は未確定で、参考測定と分ける。
