# ADR-004 .vcrコンテナ・互換性・素材保持

状態：T04でZIPコンテナ版1を実装。製品挙動は[仕様正本](../PROJECT_SPEC.md)と[保存契約](../PROJECT_FORMAT.md)に従う。容量値は検証用ポリシーの候補。

## コンテナと移行

ZIPを採用する。ZIP処理はスクリプト無効で導入した @zip.js/zip.js 2.24.0 を使い、厳格モード・CRC-32・出力ストリームで検証する。metadata.jsonにはVFXCraft固有識別子、コンテナ版、作成アプリ版を格納する。project.jsonには論理スキーマ版を含む編集文書を格納し、assets/UUID.拡張子にプロジェクト登録画像の元バイトを使用有無にかかわらず格納する。ファイル名のUUID表記を正規化し、名称は文書のメタデータで保持する。単一JSONは検査しやすいが、Base64の容量増とデコード時のメモリ負荷がある。初版では再圧縮せず元画像のバイト列を保存する。

コンテナ版と論理スキーマ版は独立させる。初版の2D・3Dファイルを固定検体として残し、将来版で再編集できることを検証する。旧版は明示的な移行を通し、移行後に現行のドメイン検証を行う。未知版は理由を返して読込を止める。後続タスクの追加フィールドは仕様決定時に既定値と移行を定義する。未知フィールドを落とした状態で上書きする経路は設けない。

## 読込・破損対策

専用識別子、対応版、必須ファイル、エントリ重複、絶対パスや親参照、CRC・展開破損、実展開容量・件数、画像形式・寸法と参照の整合性を検証する。一時領域に文書と素材を構築し、T02の検証を含む全検査が成功した場合のみ、T03の文書・履歴と素材ストアを切り替える。読込失敗では文書、履歴、素材、保存先を維持する。

## 保存と履歴

同一ファイルへの上書きを基本とする。ブラウザのファイルハンドルを利用できる場合は書込完了を確認する。非対応時は明示的にダウンロード方式へ切り替え、利用者確認まで保存済みにしない。両方式とも、保存開始時に確保したT03のスナップショットと登録画像のBlob参照を処理対象とする。書込を直列化し、書込成功またはダウンロード後の利用者確認を対象スナップショットに通知する。追加編集の状態を保存済みにしない。確認取消では保存位置を変更しない。利用者確認をアプリによるファイル完全性検証と区別する。

未保存で開く際は、保存して開く・保存せずに開く・キャンセルを提示する。保存して開く場合は、書込成功またはダウンロード保存の利用者確認を得てから読込へ進む。保存中に追加編集があれば、未保存の編集を失わないよう切替を中止して再確認できる状態に戻す。失敗時は原因を示し、再試行または別の場所への保存を選べるようにする。

## 素材の寿命と検証

Blobは素材IDで管理する。文書、Undo/Redo、プレビュー、処理中の保存から必要とされる間は保持し、Object URLは利用終了時に解放する。保存対象の画像を保持する仕組みと、履歴だけが参照する削除済み素材の保持を分ける。

T04ではAT-10/11の最小ケース、上書きと代替経路、保存中の追加編集、初版検体、破損・欠損・未知版を検証する。T11で自動保存の世代、候補と日時の表示、選択復元、容量や中断を検証する。

## 検証用の容量ポリシー

検証画面の候補は、ZIP 130 MiB、実展開合計128 MiB、エントリ単体32 MiB、JSON単体4 MiB、514エントリ（画像512件と必須JSON 2件）、画像16,777,216画素。4096×4096のRGBA画像1枚の非圧縮バッファは約64 MiBになる。ZIPの元データ、展開済みBlob、デコードバッファが同時に存在し得るため、合計・単体・画素数を別々に制限し、画像は順次検証する。130 MiBと128 MiBの差はZIPの管理情報を見込んだ候補。対象端末でのメモリ・所要時間と代表案件の素材分布を測ってから製品値を決める。コーデックはポリシーを引数で受け取る。

互換性検体は [2D](../../tests/fixtures/vcr/t04-2d-v1.vcr) と [3D](../../tests/fixtures/vcr/t04-3d-v1.vcr)。既存アプリの `?vcr-review` はT04の確認画面。自動保存・復元はT11で実装する。
