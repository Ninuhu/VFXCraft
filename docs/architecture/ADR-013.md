# ADR-013 正式エディタの統合と操作状態

状態: 採用（T10の検証状況は[T10検証記録](../T10_VALIDATION.md)を参照）

## 目的と境界

正式UI v1.0のホーム・新規作成・2D/3Dエディタを、T03〜T09の同じ文書・編集履歴・描画・保存へ接続する。プリセット収録・検索はT12、製品出力はT13、完全な環境設定・日英・両テーマ・ヘルプはT14。画面の入口と業務機能の完成を区別する。

## セッションと編集

`EditorApp`が一つの`ProjectFileFlow`を所有し、`EditorContext`を通してパネルへ渡す。選択・Auto Key・編集軸・品質・プレイヘッドはUI状態、プロジェクトの設定・キーは文書、配置・キー割当・スナップ間隔は利用者共通設定とする。複数選択の編集対象は最後のアクティブ一層のみ。

数値と色の入力はT03の排他的な連続編集で有効値をプレビューし、確定時に一履歴、Escapeや不正入力で取消。`edit.batch`は個々のコマンドにも検証を適用し、途中失敗を原子的に拒否する。グループ化・解除・複数成分の変換にも同じ経路を使う。Undo/Redoの上限・保存済み識別は変更しない。

Auto Key OFFは基本値だけを変更する。キーを持つ対象はそのキー評価が見た目へ優先する旨を表示する。ONは現在のプロジェクト時刻から対象レイヤーの開始時刻を引き、同時刻キーを更新、なければ追加する。既存キーと分割前の区間補間を保持する。開始前・範囲外・無効値・ロックは既存検証で拒否する。

数値・色・ギズモの連続入力では操作開始時刻を固定する。再生中に入力を更新しても、入力一回から時刻の異なる多数のキーを生成しない。画像取り込みはT04と正式UIで`projectImages.ts`を共有し、申告MIMEではなく実データから形式と寸法を検証してから登録する。

## 描画と操作

正式プレビューは`MaterialPreview`、時間評価はT08、階層・World/Parent LocalはT09を使う。TimelineReviewにパネル専用モードを追加し、正式UIでは重複するGPU描画器を作らない。Reactは文書操作とUI操作で更新し、描画はrequestAnimationFrameから最新の有効プレビューを読む。静止中は文書・時刻・カメラ・画像・補助設定の変更がなければ再描画を省く。

ギズモはカメラと同じ射影で描いたX/Y/ZのSVGハンドルを使う。Three.jsを追加導入せず既存のQuaternion・射影・カメラを再利用する。親ローカル軸は親のワールド行列から取得する。位置のスナップはT09の関数、姿勢・尺度は逆親変換とTRS分解を使い、Shearを近似しない。ハンドルのイベントをCanvasへ渡さず、カメラ入力との競合を防ぐ。ギズモ開始時刻は固定する。

画像Bitmap・GPU・カメラ入力・アニメーションフレームはPreviewPanelが所有し、文書切替・アンマウント時に解放する。素材BlobはProjectFileFlowが保持し、履歴に複製しない。

## 配置とショートカット

四領域（左・中央・右・下）へのパネル移動、表示切替、左右幅と下部高さの変更を採用する。自由な別ウィンドウ化は追加しない。配置は`vfxcraft.editor.layout`、キー割当は`vfxcraft.editor.shortcuts`へ保存し、.vcrには含めない。不正な設定は項目ごとに既定値へ復旧する。パネル復旧は常設の表示メニューと設定画面から可能。

キーの正本を`shortcuts.ts`へ集約し、実行・設定・説明を共有する。IME・入力欄・ダイアログ・登録中は通常のショートカットを処理しない。競合は確認後に元割当を解除する。Alt+F4、Ctrl+W/T/N/L/R、F5/F11/F12など明確な予約操作は登録拒否。Ctrl+D等のブラウザ動作を全環境で抑止する保証はしない。メニューから同じ編集を実行できる。

## 保存と復元、T11との担当変更

ユーザーのT10追加指示により、プロジェクト用の自動保存・選択復元をT11からT10へ移す。T01の検証用DBを製品保存として流用しない。既存のwriteVcr/readVcr・画像検証を再利用し、完成した.vcr Blobと日時をIndexedDBへ原子的に保存する。明示保存のmarkSavedは呼ばない。復元したプロジェクトも未保存として開始し、外部ファイルを自動上書きしない。

暫定の技術ポリシーは確定後2秒のデバウンス、最近3プロジェクトの最新一候補。製品上限や本格的な複数世代の決定ではない。T11に世代・容量・中断・競合タブ・長時間利用の追加検証を残す。完了順が前後した自動保存は開始日時を比較し、古い候補で新しい候補を上書きしない。容量不足・無効な復元は通知して初期画面を維持する。

手動保存はT04を使い、ダウンロード後の利用者確認と完全性検証を混同しない。切替確認中に追加編集があれば切替を取り消す。読込失敗で文書・画像・履歴・保存先を破棄しない。beforeunloadは未保存の文書がある場合だけ登録した標準警告を発火させる。

## 代替案と制約

- 別のUI状態ライブラリ・ドッキング・ギズモパッケージは依存を増やすため導入しない。既存のReact Contextと小さな操作部品を使う。
- 各検証画面をそのまま並べる方式は複数セッションとGPU資源が重複するため採らない。タイムラインは既存部品のパネルモードで再利用する。
- 自動復元データで手動保存済みと判定する方式は、外部ファイルへの保存と一致しないため採らない。
- UI v1.0の構造・紫アクセントは維持し、未実装のプリセット一覧や出力結果を架空の内容で埋めない。装飾・収録素材の差は検証記録へ記載する。
