# VFXCraft UI要件

版: 1.0 / 2026-11-03  
本書は「何を操作・確認できるか」を定義する。配置は定義しない。

## 1. UI設計の担当と未確定範囲

**UIレイアウト・見た目の設計者はユーザー。** 本書の機能一覧を、固定パネルや特定方向への配置として解釈しない。正式な画面構成はUI v1.0に従う。次の項目のうち画像から判断できない詳細は、確定仕様と補完ルールに従って整理する。

- 各機能の位置・幅・高さ・占有率・表示順序
- 常時表示、タブ、ポップアップ、ドロワー等の選択
- 分割・ドッキング・移動・折りたたみ方式
- 画像にない画面遷移、2D/3Dボタンの意味、配色の詳細、アイコン、フォント
- 最小画面サイズ、縮小時の優先表示、レスポンシブ配置

技術検証用の画面には「検証用UI」と明示し、製品配置の決定として扱わない。ユーザー設計の待機中も、操作コマンド、描画、保存、出力、部品単位の検証は進められる。

## 3. 操作の一貫性（設計提案）

製品要件を安定して実現するための振る舞いの案。具体的なキーや操作ジェスチャーは、UI設計時に決める。

### 編集と選択

- 選択中のレイヤー・キー・素材を識別できる。
- 入力値の単位、最小/最大、適用対象を確認できる。無効値は確定前に理由を示す。
- ドラッグや数値スクラブの連続変更は1回のUndoにまとめる。確定/取消の操作を用意する。
- ロック中、非表示中、親の状態による制約を区別して示す。
- 親子関係の循環や、選択自身への親設定を受け付けない。
- 多重選択や一括キー編集は未確定なので、必須UIとして追加しない。

### 時間とプレビュー

- 現在位置、制作FPS、出力FPS、実測FPSを混同しない表示名にする。
- フレーム送り・スナップに使う時間基準を一致させる。
- 再生速度を変えても保存されるキー時刻やエクスポート結果が意図せず変わらない。
- プレビュー用のチェッカー・グリッド等は出力対象と区別する。
- モードに無関係な3Dカメラ操作等は、対象外であることが分かる状態にする。

### 保存・復元・出力

- プロジェクト保存とエクスポートを別の操作名にする。
- 未保存変更、自動保存の状態、ファイル読込失敗、出力処理中/完了/失敗を伝える。
- 自動保存の復元が既存の編集中データを黙って置換しない。
- `.vcr`読込失敗や出力の取消で現在の編集内容を失わない。
- PNG連番・シートは画像設定、3D JSONは設定データ出力として、関係する入力だけを扱う。
- 出力サイズやフレーム数が上限を超える場合は、開始前に理由と変更すべき値を示す。上限値自体は技術検証で決める。

### 素材・プリセット

- 素材形式エラー、参照切れ、読込中を識別できる。
- 内蔵プリセットと自作プリセットを区別する。原本への上書きに依存しない。
- 名前・カテゴリ・サムネイル・検索等の具体的な選び方はUI設計で決める。50種類以上を扱える導線を検討する。

## 4. ショートカット

必須の操作カテゴリは保存・Undo・Redo・複製・削除・再生操作。キーの割り当ては未決であり、一般的な組み合わせをこの時点で確定しない。

設計時には次を満たすことを提案する。

- 日本語入力中・テキスト入力中に削除や再生の誤作動を起こさない。
- ブラウザやOSの操作と衝突する場合の扱いを決める。
- ショートカット一覧と実際の割り当てを同じデータから表示する。
- カメラ操作とオブジェクト編集の競合を避ける。

ユーザーによるキー割り当て変更はMVP-Bの確定要件ではない。

## 5. テーマ・言語・使いやすさ

確定要件はダーク/ライト、日英、設定保持、3種類のヘルプ。追加の設計提案は以下。

- 日英でラベル長が変わっても、操作名や数値が欠けない。
- 状態を色だけで伝えず、文字・アイコン等も併用する。
- キーボードのフォーカスが確認できる。入力のラベルを明示する。
- ツールチップにしか重要な情報が存在しない状態を避ける。
- 2つのテーマで、数値・選択・キー・階層・グリッドが判別できる。

## 6. UI設計の引き渡しと確認

ユーザーは[UI_LAYOUT_WORKSHEET.md](UI_LAYOUT_WORKSHEET.md)または別のデザイン資料で配置を指定する。CodexはUI-01〜UI-18との対応を確認し、不足している機能の配置だけを確認する。既存の指定と矛盾する配置を独断で補わない。

UIの実装前に、対象モード、状態ごとの表示、操作結果、日英・テーマ差、縮小時の扱いを関連付ける。配置に関係しない内部機能の実装はこの引き渡しを待たずに進める。

## UI v1.0の正式採用（2026-11-07）

[UI v1.0](design/ui/UI_v1.0/)の9画像を正式な画面構成の基準とする。v0.1は過去の参考資料。画面構成、デザインと配色を基準に、確定仕様に必要な操作、入力、説明、ダイアログ、設定、スクロールと折りたたみを補完できる。補完時は既存操作の有無を確認し、追加場所・用途・操作方法を明確にする。基本操作の発見しやすさと初心者の理解を優先し、UnityやBlenderは操作性の参考にできる。ライトテーマ、英語、画面縮小時も同じ要件を満たす。大幅なレイアウトや画面遷移の変更は事前承認を得る。画像上の文言・機能と確定仕様が矛盾する場合は確認する。

保存・読込には未保存時の三択、原因と再試行・別の場所への保存、ダウンロード開始と利用者による保存確認、T11の復元候補と日時の選択状態を追加する。利用者確認をアプリの完全性検証として表示しない。詳細は[保存形式](PROJECT_FORMAT.md)を参照。

## T05の検証UI
?particles-review は描画・発生・空間・品質・保存の開発用画面。正式UI v1.0への本格統合はT10。

## T06検証UI
/?particles3d-review は3D発生設定、カメラ入力、二種のビルボード、保存と履歴を確認する開発用画面。正式UIの採用状態は維持し、製品配置はT10。

## T07検証UI
`/?materials-review` にマテリアル選択、寿命・空間の色と透明度、合成とBloom、背景の項目別継承と品質を配置する。数値はEnterまたはフォーカス離脱で確定し、Escapeで入力を取り消せる。保存・履歴はT04と共通。製品UIへの統合はT10、利用者共通設定の製品画面はT14。

## T08検証UI
`/?timeline-review` にタイムライン、レイヤー・トラック・キー行、再生位置、再生と速度、秒・フレーム入力、ズーム・スナップを配置する。キー衝突と尺短縮は確認モーダルを表示し、キャンセルに初期フォーカスを置く。数値入力はEnterまたはフォーカス離脱で確定し、Escapeで取り消す。製品画面はT10で統合する。

## T09検証UI
`/?hierarchy-review` に階層ツリー、展開・選択・親変更・親解除・複製・削除、ロックと表示、Transform編集、World／Parent Local、位置スナップとグリッドを配置する。祖先ロックを区別し、拒否理由を表示する。ドラッグのドロップ候補を有効・無効で区別し、選択メニューからも同じ親変更ができる。T08のタイムラインは同じ文書・履歴・再生ヘッドを共有する。正式UIへの統合はT10。

## T10 正式画面

通常の`/`を正式ホームとし、9画面の基準を維持する。正式エディタでは左にHierarchy、中央にPreview、右にProperties、下にTimelineを初期配置する。四領域への移動・サイズ・表示と復旧を提供する。T01の独立技術検証は`/?technical-review`、T04〜T09の既存検証URLは継続。

複数選択時はアクティブ一層だけを編集し、その対象を明記する。基本値とAuto Keyの編集先を表示する。World/Parent LocalとSimulation Spaceを別名で表示する。ギズモ・数値・色の取消と履歴、説明・現在のキー割当を[ADR-013](architecture/ADR-013.md)に従って接続する。主要パネルの初期キーはAlt+Shift+1=Hierarchy、2=Properties、3=Timeline。

自動保存・復元はユーザーの明示承認によりT10で基礎実装する。候補名と日時、復元・保留を示し、明示保存と混同しない。プリセット・素材・出力・設定・ヘルプ画面の入口があっても、T12〜14の全機能の完成とは扱わない。

## T11 保存状態と復元UI

正式UIにファイル処理中、自動保存待機・実行・成功・失敗と再試行を補完する。復元候補は名前・モード・日時・タブ・世代を示し、一覧更新と保留を提供する。保留でデータは削除しない。メタデータ破損は件数を通知し、アーカイブ破損は選択時に拒否する。容量不足は.vcrへの明示保存を案内する。日時は端末時計の表示値であり、異なるタブの内容の新旧を保証しない。ブラウザ内保存が恒久バックアップではない説明を表示する。T11のユーザー追加指示では必要な配置調整に個別承認を求めない。参考PNGは変更しない。
