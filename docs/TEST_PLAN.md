# VFXCraft 検証・受け入れ計画

版: 1.0 / 2026-11-03  
状態: 検証計画。アプリの検証は未実施。

## 1. 判定方針

[PROJECT_SPEC.md](PROJECT_SPEC.md)のMVP-B必須41項目をAT-01〜16で確認する。設計提案に由来する詳細な振る舞いは、関連ADRの採用後に期待値を固定する。ユーザー設計のUI統合も完成条件に含める。

自動化は、時間評価・履歴・階層・保存往復・出力など壊れると制作データに影響する部分を中心にする。見た目、操作性、日英・テーマは代表環境で人が確認する。細かな部品の実装をなぞるだけのテストは増やさない。

## 2. 検証用データ

| データ | 含める内容 |
| --- | --- |
| FX-2D | 通常/ピクセル描画、連続/Burst、複数レイヤー、アルファ/加算、グラデーション、基本Bloom、透過素材 |
| FX-3D | 3D粒子/ビルボード、連続/Burst、親子変換、材質、カメラ操作 |
| FX-TIME | 全必須キー、複数の開始時間、ループ境界、先頭/末尾、フレームスナップ |
| FX-HISTORY | 親子・グループ、ロック/非表示、複製、素材変更、100操作を超える履歴 |
| FX-BROKEN | 識別不正、未知の版、素材欠落、循環、重複ID、無効な数値、破損画像 |
| FX-LARGE | 基準端末で測定する粒子数・素材容量・出力サイズの段階的な負荷 |

名称は検証用データの識別名であり、収録プリセットとしての指定ではない。乱数シードと時間条件を固定し、画像比較では基準環境と許容差を記録する。

## 3. 受け入れ項目

### AT-01 Webと独立モード

対象: REQ-Q01-01、REQ-Q02-01。

選定した対応ブラウザで起動し、2Dと3Dの制作フローへそれぞれ入れる。対象外の操作が混入せず、モードと保存値が一致する。変換・混在を勝手に追加していない。対応環境とモード切替仕様はADRの期待値を使う。

### AT-02 連続発生とBurst

対象: REQ-Q05-01、REQ-Q05-02。

2D/3Dの代表例で連続発生と一括発生を別々に確認する。再生・リセット・シークで粒子が意図せず蓄積しない。設定を変更し、保存・復元後も保持する。シード等の再現性方式を採用した場合、同条件で発生結果を比較する。

### AT-03 2D描画と合成

対象: REQ-Q06-01、REQ-Q08-01、REQ-Q08-02、REQ-Q08-03、REQ-Q08-04、REQ-Q08-06。

複数レイヤー、テクスチャ、アルファ/加算、グラデーション、通常/ピクセル描画、基本Bloomを見本と比較する。重なり、透明部分、色、拡大時のピクセル、発光の切替を確認。描画内容が保存値と一致する。

### AT-04 3Dとカメラ

対象: REQ-Q08-05、REQ-Q11-01。合成・グラデーション・基本Bloomの3D対応部分もAT-03と合わせて確認。

3D粒子の奥行き、ビルボードの向き、透明描画順を代表見本で確認する。カメラの回転・ズーム・平行移動・リセットが機能し、カメラ操作でオブジェクト設定を誤変更しない。

### AT-05 タイムライン・キー・再生

対象: REQ-Q03-01、REQ-Q03-02、REQ-Q03-03、REQ-Q07-01、REQ-Q11-03、REQ-Q11-04。

2D/3Dそれぞれで位置・回転・サイズ・色・透明度のキーを追加・移動・変更・削除する。開始時間を変え、補間値と時刻を照合する。再生/一時停止/リセット/ループ/コマ送り/速度変更と任意時刻へのシークを確認。プレビュー速度が出力FPSやキー時刻を書き換えない。開始前、キーの同一時刻、範囲終端の扱いはADRで固定する。

### AT-06 レイヤーと階層

対象: REQ-Q12-02、REQ-Q12-03、REQ-Q12-04。

追加・削除・並び替え・表示切替・複製・改名・ロック・グループ化・親子関係を実行する。親子の変換、親の削除、再親子化、ロック/表示継承は採用した仕様と照合。循環を拒否し、複製でID/キー参照を正しく再生成する。2D/3D両方でUndo/Redoと保存往復まで確認する。

### AT-07 最大100操作のUndo/Redo

対象: REQ-Q12-01。

- 区別できる101件の有効編集後、直近100件をUndoできる。さらに戻そうとして状態が壊れない。
- 100件をRedoすると編集後へ戻る。Undo後の新規編集では、採用方針どおりRedoを破棄する。
- 数値、レイヤー、キー、素材参照、階層の各変更を含める。
- ドラッグの集約・取消、無効操作、履歴上限に達した状態、保存位置へのUndoを確認する。
- 参照を戻した素材が描画・保存できる。大きい画像を100回複製するような履歴構造になっていないことを測定で確かめる。

履歴操作単位や保存済み判定などの詳細はADR-005を期待値とする。

### AT-08 スナップとショートカット

対象: REQ-Q12-05、REQ-Q12-06、REQ-Q12-07。

保存・Undo・Redo・複製・削除・再生の割当を確認。入力欄・日本語変換中の誤動作、ブラウザとの競合、ヘルプとの一致を確認する。フレームスナップ、2D位置グリッド、3D位置グリッドを正負の値・階層下の対象で確認し、基準空間と間隔がADRと一致する。

### AT-09 プリセット

対象: REQ-Q09-01、REQ-Q09-02。

収録一覧で一意な初期プリセットが50種類以上あることを数える。全件を読み込み、参照素材がそろっていることを確認。内容の差、名前・対応モード、利用条件の記録を検収する。代表例で編集→自作保存→読込→再編集→`.vcr`保存→出力まで通す。内蔵原本を壊さない。

### AT-10 素材インポート

対象: REQ-Q09-03。

PNG・JPG・WebPをそれぞれ実際にデコード・表示し、プロジェクト保存/復元後も確認する。PNG/WebPの透過を含める。破損・対象外形式を受け付けず、現在の素材参照を失わない。見かけの拡張子と実データが違う場合の挙動も記録する。

### AT-11 `.vcr`保存往復

対象: REQ-Q10-01、REQ-Q04-01の3D保存部分。

2Dと3Dの全必須データを保存→別セッションで開く→再編集する。階層、順序、表示/ロック、開始時間、キー、発生、材質、描画方式、素材本体の整合を比較。3D設定がJSON表現で保持されていることを確認する。未知版、破損、素材欠落、循環等の読込失敗で現在の作業が変わらない。ZIPの場合はその方式に必要な検証も行う。

### AT-12 自動保存・復元と設定保持

対象: REQ-Q10-06、REQ-Q14-03。

画像を含む編集を自動保存し、ブラウザ再起動後に復元する。保存途中の中断、容量不足、複数の復元候補、最新の正常世代を確認する。テーマ・言語・プレビュー設定が保持され、別プロジェクトを開いても利用者設定が意図せず失われない。具体的な世代数等はADR-004を期待値とする。

### AT-13 PNG連番とスプライトシート

対象: REQ-Q10-02、REQ-Q10-03、REQ-Q10-05。

解像度・FPS・透過・範囲を変え、フレーム数、番号/順序、寸法、境界フレームを確認。シートの各セルを同じ時刻の連番画像と比較する。透過出力にチェッカー/グリッド/操作表示が混入しない。基本Bloomと透明背景、ピクセル描画を確認する。速度変更や画面の実測FPSで出力結果が変わらない。上限超過、失敗、取消で編集内容が保持される。採用前の半開区間案を確定済みとして期待値にしない。

### AT-14 3D JSON

対象: REQ-Q04-01、REQ-Q10-04。

出力をJSONとして解析し、スキーマ、単位/軸、階層、連続/Burst、材質、キー、素材参照を確認する。内部UI状態や一時URLに依存しない。保存とエクスポートの操作が分かれている。特定ゲームエンジンとの互換性や再インポートを、未決のまま合格条件へ追加しない。

### AT-15 プレビュー・環境・ヘルプ

対象: REQ-Q11-02、REQ-Q11-05、REQ-Q14-01、REQ-Q14-02、REQ-Q14-04。

背景色・透明チェッカー・グリッドを確認。実測FPSと現在粒子数は更新され、制作/出力FPSと区別できる。両モード×日本語/英語×ダーク/ライトで主要フローを確認し、読めない文字や欠けた入力がない。ツールチップ、初心者ガイド、ショートカット一覧が開き、内容が実装と一致する。

### AT-16 全体統合・性能・スコープ

対象: 全必須要件、UI配置制約、MVP-B完成条件。

ユーザーのUI設計資料と製品画面を照合する。プリセット→素材変更→階層/キー編集→Undo/Redo→手動/自動保存→復元→各出力を通す。対応ブラウザと基準端末で代表負荷のFPS、粒子数、メモリ、保存/出力時間を測る。閾値はADR-007で事前に決め、未達を隠して合格にしない。

AIが接続されていなくても基本フローがすべて通ることを確認。将来機能の未実装はMVP-B必須の不合格理由にしない。基本Bloom、3D、階層、50種類以上、自動保存を将来へ移していないことを点検する。

## 4. 検証記録の形式

```text
検証日 / コード版:
対応環境・基準端末:
AT ID / 要件ID:
テストデータ・シード・時刻:
期待値を定めた仕様/ADR:
結果（合格 / 不合格 / 未実施）:
証拠（ログ・比較値・画像等）:
制約・残件・修正タスク:
```

この資料一式に対する文書の確認と、上記のアプリ受け入れ検証は別。アプリの実装前にATを合格として記録しない。
